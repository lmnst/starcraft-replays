模型指挥自主迭代（RSI）

本模块记录大模型在星际争霸 1.16.1（神族，地图 Destination）中，使用与人类指挥相同的顶排按键指挥层进行实时局内指挥 + 赛后自主复盘迭代的完整过程。所有版本编号、对局结果、帧号与修改内容均取自本地原始对局与复盘日志。

指挥接口（沿用人类指挥最终版 11 键）

局内决策层与人类指挥共享同一套 toprow_commands_v17 指挥层：常规采矿、造兵、建筑与科技由底层 Bot 负责，大模型在关键事件（开局、敌情变化、交战接触、定期检查）触发时决定是否按键接管，高频条件还可蒸馏进本地快速规则（rules.py）。

按键功能作用简述
1探机避险接管侦察或受威胁探机持续脱险
2强制采矿屏蔽探机参战/追敌，强制维持采矿与建造
3 / 4小队 / 全队模式切换后续战术指令作用于 1/4 兵力小队还是全部作战部队
5攻近敌／分矿建筑优先清理近点或分矿建筑，沿途迎击敌军，完成后撤离待命
6主基地区域清场锁定敌方主基地区域，沿途先清敌军与炮台，再拆外围水晶与核心
7持续区域警戒在警戒区迎击敌兵和炮台、忽略探机，限制追击
8原地集结等援兵前线固守待援，受压时前往共同局部避险点
9安全撤离集结前线先脱战，与后方新兵在安全点汇合待命
0全军回防全军分守主矿与分矿，限距拦截入侵敌军
-全局重置解除所有人工/模型接管任务，交回底层 Bot 自动控制

第一批：10 轮 × 2 局（9 对手轮换，规则与运营参数探索）

目标：跑通「实时指挥 → 赛后多工具复盘 → 自主修改策略/规则/参数 → 校验上线」的完整闭环，观察模型在面对 9 个不同对手轮换时的自主迭代表现。

实验条件说明：第一批由 20261124-145321-768219（前 3 轮，使用固定 Baseline.dll，模型只能改 rules.py 和 strategy.md）与 20261124-193345-717393（后 7 轮，切换为可调参的 MacroBot.dll，新增 build_config.json）连续衔接组成。中途定位并修复了 3 处基础设施问题：局内多 JSON 回复解析、PurpleWave 在 JDK 21 下缺 --add-opens 导致启动即崩溃（故第 3 轮 B-5 对 PurpleWave 的胜局为对手崩溃导致的无效胜局，未纳入复盘）、以及并行时 Java 对手连错客户端（修复为 Java 对手单独一波运行）。

第一批暴露的瓶颈（为什么升级为第二批）

  1. 9 个对手轮换导致样本过稀、无法验证修改效果：同一个对手约 4.5 轮才重逢一次，复盘只能针对刚刚输掉的那个对手打补丁，导致炮台时间在 4800 与 6500 之间来回震荡。
  2. 无版本准入/淘汰机制：每次修改直接覆盖生效，退步版本会继续往下演进。
  3. 只改参数难以解决结构缺陷：盲目 6 兵进攻、无快攻识别、叮当不跟部队、矿钱被建筑卡死等问题都在底层 C++ 逻辑里，仅靠调 build_config.json 改不动。

第二批：24 轮 × 4 局（固定 3 对手 + 冠军/挑战者淘汰 + 自主改 C++ 源码）

第二批（20261124-224218-659920，共 24 轮 96 局）针对第一批的瓶颈做了三项核心升级：

  • 固定核心对手池：每轮候选版本对阵固定 3 个对手（PylonPuller、Steamhammer、BananaBrain），外加 1 局当前冠军版本复测（2×2 并行，每轮 4 局），让每次改动的得失都能在同一基准上直接对照。
  • 严格晋升 / 淘汰机制：引入纯 L0 综合评分（结合胜负、存活、科技里程碑、战损比等），候选版本必须实现胜率或综合分提升且不能在单对手上明显退步才能晋升为新冠军；否则立即淘汰并回退到当前冠军重新诊断。
  • 开放修改底层 C++ 源码：模型复盘时可直接修改 MacroBot.cpp 与 build_config.json，自动编译并通过校验后进入实机评测。

主线晋升谱系（23 次提案中 7 次晋升：v1 → v8）

初始基线 v1（第 1 轮）

起始版本在第一批基础上修复了主动炮台优先级与分矿冷却。第 1 轮基线评测（对 PylonPuller 1 胜 1 负、Steamhammer 0 胜 2 负、BananaBrain 0 胜 1 负）暴露出核心问题：底层 Bot 只要凑够 6 个兵就无脑前压，屡次在敌方门前被兵力占优的龙骑全歼。

第 2 轮：c1 晋升为 v2（MacroBot.cpp Δ34 行 + build_config.json）

  • 问题诊断：3 场败局均为 6–8 个无射程狂热者过早出击送掉，且开气偏晚导致龙骑出不来。
  • 模型改动：改写交战阈值——改为我方兵力 ≥ 8 且估算战力 ≥ 记忆中敌军战力 1.4 倍 + 4 才发起进攻，战力跌破敌方 0.9 倍或不足 4 兵即撤回集结；同时提早开气（gas1_zealots: 3→1、gas1_frame: 4400→3200）。
  • 评测结果：晋升 → v2 对 PylonPuller 获胜（L0 93.2），对 Steamhammer / BananaBrain 均分显著抬升（63.7 / 52.5）。

第 5 轮：c4 晋升为 v3（MacroBot.cpp Δ29 行）

  • 问题诊断：前两轮（c2 改开矿点、c3 改 6000 帧主动叮当）均因表现退步被淘汰；复盘发现面对 Steamhammer 早期狂热者快攻时，2 兵营等 12 农、BY 排在前面，且拉 17 个探机硬扛导致 6000 帧即崩盘。
  • 模型改动：新增早期快攻检测（rushSeen：6500 帧前在我方主矿 1600px 内见到 ≥2 敌方初期兵即触发），触发后立即补 2 兵营与 3 兵营并优先于科技，同时比较家门口威胁战力，避免探机白白送死。
  • 评测结果：晋升 → v3 稳住 PylonPuller 胜局（91.5），抗快攻能力提升。

第 7 轮：c6 晋升为 v4（MacroBot.cpp Δ14 行）

  • 问题诊断：c5 尝试补炮台未果被淘汰；日志显示我方侦察探机早在 3360–3480 帧就合法看到了对手主矿的双兵营无科技开局，但 v3 的快攻响应要等到敌兵走到家门口（晚了约 2000 帧）才启动。
  • 模型改动：将 rushSeen 前移至侦察阶段——5000 帧前只要侦察到对手 ≥2 兵营（且无气矿/科技）或 3800 帧前见到狂热者即立刻触发防快攻出兵。
  • 评测结果：晋升 → v4 首次正面击败 Steamhammer（L0 93.5）。

第 8 轮：c7 晋升为 v5（MacroBot.cpp Δ15 行）

  • 问题诊断：虽然已提前侦察到 BananaBrain 快攻，但防快攻期间仍把钱花在气矿（75）、BY（150）和过早的 3 兵营上，气矿攒到 120 没用上，正面只够出 4 个狂热者。
  • 模型改动：侦察到快攻后，6500 帧前（无隐刀信号）凑齐 4 兵之前停止造气矿与 BY、暂停采气，把 225+ 晶体全转成狂热者；3 兵营要求余钱 ≥200；且家里兵力处于劣势时禁止单位追出 260px 以外送死。
  • 评测结果：晋升 → v5 连续击败 Steamhammer（L0 93.4），且对 PylonPuller（71.3）与 BananaBrain（45.5）均分全面高于 v4。

第 11 轮：c10 晋升为 v6（MacroBot.cpp Δ10 行 + build_config.json）

  • 问题诊断：c8、c9 尝试局部补防均未通过；复盘发现 v5 输给隐刀并非缺静态防御，而是 BY 和 VR 一直被造兵抢光矿钱（BY 拖到 5736 帧、VR 拖到 9360 帧分矿之后），叮当比隐刀晚了 1500 帧。
  • 模型改动：在 production() 中为待建的 BY / VR / 叮当建筑强制预留矿气；在无家门口威胁时把 VR 排在二基地之前，并将 robo_frame 9000→7800、robo_army 10→8。
  • 评测结果：晋升 → v6 再次击败 Steamhammer（L0 88.4），科技节奏明显提前。

第 17 轮：c16 晋升为 v7（MacroBot.cpp Δ37 行）

  • 问题诊断：从第 12 到第 16 轮连续 5 次探索（c11–c15：拉农阈值、分矿时机、5400 帧主动叮当、中场追击限制、看 BY 出反隐）均因在某一对手上退步被淘汰。第 17 轮定位到真正病灶：我方明明已有 2 个叮当和 13 个兵，却因为叮当一直停在主矿，导致分矿的隐刀全程隐身屠光主力。
  • 模型改动：新增 cloakMemory 记住最近合法看到的隐形攻击单位位置与帧号，并分配双叮当职责——0 号叮当贴近主力追猎最近隐形目标，1 号叮当守护基地，同时在追猎时缩小规避防空半径。
  • 评测结果：晋升 → v7 反隐实战立竿见影，v7 在后续累计对 PylonPuller 取得 3 胜 0 负（均分 85.6），成为最稳的阶段性突破。

第 22 轮：c21 晋升为 v8（MacroBot.cpp Δ7 行 + build_config.json）

  • 问题诊断：第 18–21 轮（c17–c20：修气体预留负值、对炮台开局补反隐、防追击牵引、6000 帧主动炮台）先后出现对 PylonPuller 退步或提升不足被淘汰（其中 c17 对 Steamhammer 打满 36,000 帧平局、L0 89.6）。第 22 轮转向开局矿钱卡位：2 兵营在 3240 帧就要建，却被狂热者和探机抢钱拖到 4632 帧，刚好撞上 BananaBrain 4680 帧的狂热者压境。
  • 模型改动：为 2 兵营强制预留 150 晶体，gate2_workers 从 12 降至 10，并让分矿逻辑跳过敌方建筑 320px 内点位及拉黑失败选址。
  • 评测结果：晋升 → v8 最终冠军版本：对 PylonPuller 获胜（90.7），对 BananaBrain 得分提升至 60.5（三对手均分全面超越 v7）。末两轮 c22（进攻阈值改保守）与 c23（5700 帧主动炮台）均未胜过 v8，最终保留 v8 作为收官冠军。

被淘汰探索的共性观察（16 次淘汰）

  • 静态防御 / 过早反隐常引发经济退步：c3、c5、c13、c20、c23 试图靠固定帧号提前下炮台或叮当，往往在未遇快攻隐刀的对局里拖慢正面产兵，被淘汰机制拦下。
  • 单一对手特化易破坏已建立优势：c12、c14、c15、c18、c19 虽然在某一场打出高分甚至赢下 Steamhammer（如 c12 93.6、c18 93.8），但同时在 PylonPuller 上失守，因此被 regression_on_PylonPuller 拒绝晋升。
